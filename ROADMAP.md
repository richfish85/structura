# Structura roadmap

Status labels are deliberate: `complete`, `in progress`, `next`, `planned` and `exploratory` are not interchangeable. Each implementation increment requires its own milestone before work begins.

## Goal

Build a definitive evidence-backed hardware tracker: identity-resolved, connected, time-aware and traceable. SQL owns the record. Visuals explain it. Practical pathways make selected knowledge immediately useful.

## MVP 0 — SQL and evidence foundation · complete

- Ordered SQLite schema and controlled ontology proposals.
- Bounded scout, verifier, normalizer, auditor and human-review workflow.
- Claim-level provenance, uncertainty, discrepancies and reproducible builds.
- 1997 and 1998 CPU, GPU and storage research cohorts retained as provisional records.
- Six Nokia phone models are staged as provisional 1997–1998 research candidates under an era-aware Phones → Smartphones / Legacy Phones browse hierarchy. This is a sample, not a census.

## MVP 1 — Connected explorer · complete, human trial pending

- Public static explorer generated from the SQL snapshot.
- Search, dossiers, relationships, sources and visible uncertainty.
- Samsung 970 EVO example connecting product, family, components, form factor, interface and protocol.
- Automated and live-browser validation complete; real-person usefulness remains unproven.

## MVP 2 — Reusable visual confirmation · in progress

The owner approved moving visual work ahead of the unavailable baseline participants on 2026-09-16. The published explorer remains the comparison baseline.

1. One opt-in Three.js visual relationship path is implemented on the connected SSD dossier.
2. The current dossier, component list, connections and evidence routes remain the fallback and baseline.
3. Run the deferred trial against the enhanced page and record whether the visual improves comprehension.
4. Define the shared intent-to-evidence decision contract with one PC and one phone worked example.

Visuals are derived explanations. Position, appearance and animation do not create hardware facts.

See the [visual adoption plan](docs/visual-adoption-plan.md).

## MVP 3 — Immediate-use pathways · planned

- **Can I keep this PC?** A dated Windows 11 readiness explanation for a known PC configuration.
- **Will this phone charging setup do what I expect?** A phone–cable–charger capability explanation.
- Both use one evaluator and the same SQL identities, relationships, constraints and evidence.
- `Unknown` remains a valid result; no shopping rankings or blanket compatibility promises.

See [public-use-cases.md](docs/public-use-cases.md) and [pathway-implementation-plan.md](docs/pathway-implementation-plan.md).

## MVP 4 — Evidence contribution loop · exploratory

Possible direction: missing records become bounded quests to identify an item, locate a source, verify a claim or resolve a conflict. Submitted material would enter non-canonical staging and require independent review.

Before approval, define claim-level recognition, canonical promotion, contribution terms, source/image rights, privacy and redaction, duplicate handling, moderation, abuse controls and the multi-user backend. Participation or popularity must never determine factual status.

## MVP 5 — Engagement and object-centred community · exploratory

Possible direction: visual map completion, collections, contributor acknowledgement, followed devices, source discussion and community research quests. Engagement progress must remain separate from evidence credibility and canonical review.

Do not begin with a generic social feed, global authority score, raw-submission leaderboard, direct messages or rewards for unsupported volume. Accounts and community features require a dedicated threat model and moderation plan.
